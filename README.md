# Linear Algebra Lab | مختبر الجبر الخطي

تجارب لفهم الجبر الخطي بالحساب والرسوم، بالتوازي مع دراسة Gilbert Strang،
وباستخدام **NumPy وSciPy وSymPy وMatplotlib**.

## بنية المشروع

```text
LinearAlgebra/
├── README.md
├── .gitignore
├── requirements.txt
├── .vscode/                         # إعدادات المشروع وتوصيات الإضافات
├── notebooks/
│   └── Ax_equals_b_organized.ipynb  # النسخة الأساسية للدراسة والتطوير
├── archive/
│   ├── README.md
│   └── Ax=b.ipynb                   # تسلسل التجارب الأصلية محفوظ للمراجعة
└── .venv/                          # بيئة محلية، مستبعدة من Git
```

ابدأ من [الدفتر المنظّم](notebooks/Ax_equals_b_organized.ipynb).
يحتوي شرحًا عربيًا وملخصًا إنجليزيًا وفحوصًا رياضية ورسومًا للتجارب التالية:

- الأنظمة الخطية والحل الوحيد والحلول غير الوحيدة.
- الحل الخاص والنواة وخط الحلول.
- الفضاءات الأساسية الأربعة والتعامد.
- المحدد والتحويلات الهندسية: تمديد، انهيار، عكس التوجّه، وقص.
- الإسقاط على خط والمربعات الصغرى، داخل فضاء الأعمدة وخارجه.

دفتر الأرشيف يحتفظ بالتجارب الأصلية وترتيبها. أُضيف فقط شرح في بدايته
ومعالجة لمحاولتي حل المصفوفة المنفردة حتى لا يتوقف التشغيل؛ راجع
[ملاحظات الأرشيف](archive/README.md).

## التشغيل داخل VS Code

1. افتح هذا المجلد كاملًا في VS Code.
2. ثبّت إضافتي **Python** و**Jupyter** إذا لم تكونا مثبتتين.
3. البيئة المحلية `.venv` مجهّزة على هذا الجهاز. افتح الدفتر ثم اضغط
   **Select Kernel → Python Environments** واختر `.venv/bin/python` داخل هذا المشروع.
   إعداد المفسّر في `.vscode` يساعد اكتشاف البيئة؛ قد يلزم اختيار النواة يدويًا لأول مرة.
4. اختر **Restart Kernel** ثم **Run All** للتحقق من التشغيل من البداية.
   شغّل الدفتر الأصلي بالتسلسل؛ بعض خلاياه تعتمد على خلايا سابقة.

عند إعداد المشروع على جهاز جديد، افتح **Terminal → New Terminal** داخل VS Code:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

تم التحقق محليًا باستخدام Python 3.12. إصدارات المكتبات التي اجتازت التشغيل
موثقة في `requirements-tested.txt`؛ لإعادة تلك البيئة تحديدًا استخدم:

```bash
python -m pip install -r requirements-tested.txt
```

الدفتر المنظّم يطبع إصدارات المكتبات في خلية الإعداد. عند تغيير المدخلات،
راجع التوقعات الرياضية وعبارات `assert` المرتبطة بها ثم أعد تشغيل التجربة كاملة.

## إضافة تجارب Strang القادمة

اترك الدفتر الحالي مرجعًا جامعًا، وأضف كل تجربة جديدة في `notebooks/`
باسم واضح مثل `02_Elimination.ipynb`، ثم `03_Eigenvalues.ipynb`
و`04_SVD.ipynb`. هذه أمثلة لأسماء مستقبلية وليست ملفات موجودة أو ترقيمًا لمحاضرات MIT.

استخدم في كل دفتر: سؤال التجربة، التوقع الرياضي، استيراد المكتبات،
تعريف المدخلات، الحساب، الرسم، فحص النتيجة، ثم خلاصة قصيرة.
اجعل كل دفتر قابلًا للتشغيل من نواة جديدة، وتجنّب الاعتماد على متغيرات دفتر آخر.

## حفظ التغييرات على GitHub

من **Source Control** في VS Code:

1. راجع الملفات والتغييرات، بما فيها نقل الدفتر إلى `notebooks/`.
2. تأكد أن `.venv` و`.env` والبيانات الحساسة لا تظهر ضمن الملفات التي ستضيفها.
3. اختر **Stage Changes** للملفات المقصودة ثم **Commit**، مثل:
   `Organize linear algebra notebooks and document reproducible setup`.
4. استخدم **Push** أو **Sync Changes** لنشر التعديل عند رغبتك.

`.gitignore` يستبعد البيئة والأسرار الشائعة، لكنه لا يزيل محتوى حساسًا كتبته داخل
خلية أو مخرج دفتر؛ راجع المخرجات قبل نشر تجارب جديدة.
